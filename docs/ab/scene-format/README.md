# M2 proof — the scene format reproduces both hand-authored scenes

**Milestone 2 (ADR-001):** a declarative scene format (JSON, v1)
and its loader (`talerender --scene-file <path>`, `src/scenefile.rs`),
proven by re-expressing the only two hand-authored scenes —
`--scene ab1` (Onoda S01 jungle camp, §28) and `--scene dof-chart`
(the M3 bokeh gate chart) — as data in `scenes/*.scene.json`, and
A/B-ing each format render against the hand-authored render from
the **same binary on the same adapter**. Specification:
`docs/scene-format.md`.

> **Maintenance, 2026-11-14 (M6 — see `MAINTENANCE.md`):** the
> ab1 reference pair has been refreshed from the current binary.
> The M2 ab1 number below (95.170 dB) is the historical verdict
> for a pre-composer world: M4's painter rework and M5's
> hand-authored composer (which format v1 cannot express, spec
> §12) have since diverged the scene's two render paths, so the
> refreshed ab1 pair (21.820 dB) measures the composer gap as
> well as the format — with bisection evidence that the loader
> did not regress. The dof-chart verdict stands exactly as
> measured at M2 (re-verified: file render bit-identical, pair
> 84.486 dB), and remains the pure format-fidelity proof
> alongside the M6 telemetry payload equality.

## Verdict — PASS, both scenes, far above the 45 dB bar

| scene | PSNR | mean \|Δ\| / channel | % px max-channel Δ > 10 | % px Δ > 0 | max Δ |
|---|---|---|---|---|---|
| ab1 | **95.170 dB** | 0.00002 | **0.000 %** | 0.003 % (63 px) | 1 |
| dof-chart | **84.486 dB** | 0.00023 | **0.000 %** | 0.023 % (480 px) | 1 |

No pixel in either frame differs by more than **one sRGB LSB**.
The format lost nothing measurable: same staging, same colours,
same scatter placement (the sin-hash is reproduced exactly, spec
§6), same draw count (ab1: 334 draws on both sides), same bokeh
chain for the chart (the file requests it via `post.bokeh`).

Per-scene evidence in `ab1/` and `dof-chart/`: `original.png`
(hand-authored render, the reference), `native.png` (scene-format
render), `side-by-side.png`, `diff.png` (×4 amplified — visibly
black at this scale; the differences are single-LSB),
`metrics.json`. Both side-by-sides were viewed first-hand: the
halves are indistinguishable — trees, hills, tufts, fire, Onoda,
rifle and the "fighting" caption align exactly; the chart's ten
panels match blur-for-blur including the foreground-bleed panel.

## How the pairs were produced

- Binary: the CI artifact of run **43484074039** (commit
  `9398540`), built on ubuntu-22.04 — the loader commit plus its
  test fix. Renderer on both sides: **llvmpipe (LLVM 20.1.2, 256
  bits), Mesa 25.2.8, Vulkan** (software; no performance claim is
  made anywhere in this package — lavapipe figures would be
  meaningless, per §26.5).
- `original.png`: `talerender --scene ab1` / `--scene dof-chart`.
- `native.png`: `talerender --scene-file scenes/ab1.scene.json` /
  `scenes/dof-chart.scene.json`, run from the repo root so the
  ab1 caption texture path resolves.
- `metrics.json` by `scripts/ab_metrics.py` (the house metric
  definition from the §28 package: PSNR on RGB, mean |Δ| per
  channel, % of pixels with max-channel |Δ| > 10).
- The scene files themselves were generated by
  `scripts/make_scenes.py`, a formula-for-formula transcription of
  `build_scene()` / the chart's `panel_geometry()` (every hash
  placement, colour shade and transform written out as data),
  checked into this package so the transcription is auditable.

## Where the residual single-LSB pixels live (analysed, not hidden)

- **ab1 — all 63 differing pixels sit in the caption strip**
  (x 240–720, y 1200–1440). The caption is a camera-facing
  billboard: the hand-authored code builds its four corners from
  the eye/target basis per-corner in f32; the format bakes the
  billboard *centre* into the file in f64 and the loader
  re-derives corners from the file's camera. The resulting shift
  is sub-ULP at the quad, and a few glyph-edge texels round the
  other way. Nothing else in the 2,073,600-pixel frame differs.
- **dof-chart — 480 differing pixels (0.023 %), max Δ = 1,**
  spread across the blurred panels: last-bit rounding where the
  loader composes a per-draw MVP (view·projection·model) where the
  hand-authored chart uploads a single projection-uniform chain,
  and the depth prepass reads positions from a position-only
  vertex buffer. The bokeh arithmetic itself is the same WGSL.

## The f32 lesson (why the first pass scored 71.9 dB)

The generator's first pass wrote *f64 approximations* of the
hand-authored f32 staging literals (tree scale 1.3 as a double,
blob offsets, palm angles). Result: PSNR 71.85 dB, 89 differing
pixels with silhouette-edge flips up to Δ = 47 on near geometry —
still above bar, but a real loss. Rewriting every computed value
through an exact f32 round-trip (products of two f32s are exact in
f64, so the transcription can be bit-faithful) produced the
95.17 dB result above. This is now a stated law of the format
(spec §11): **transcribed staging must carry exact f32 values.**

## Regression — the hand-authored modes are untouched

The M2 work extracted ab1's/dof's shared helpers into
`src/scene.rs` (commit `6b62af5`) and parameterised two painters
(grass base colour, sky gradient colours — ab1 passes its own
values). Proof that nothing moved: renders of `--scene m1`,
`--scene ab1` and `--scene dof-chart` from the final binary are
**pixel-identical** (PSNR ∞, max Δ = 0) to renders from the
pre-M2 binary, which were themselves verified pixel-identical to
the committed `docs/ab/*/native.png` references. The refactor
commit's own CI binary was checked the same way before the loader
landed on top of it.

## What the format could NOT express from these two scenes

Declared per the seat's honesty rule (full list: spec §12):

1. **The character.** ab1's Onoda card is a `code-ref` node
   (`ab1-onoda-card`): the painter is M4 (ADR-001 Decision 4).
   The card's *texture* is a named generator (`onoda-card`),
   exactly as the environment textures are named painters.
2. **The rifle** is a `code-ref` (`ab1-onoda-rifle`): its
   transform derives from the painter's hand position via
   `syncAttachments` — painter data that does not exist until M4.
3. **Roughness** is declared in the material schema but **not
   consumed** by the v1 shader — carried for M5's PBR binding.
4. Everything else in both scenes — 376 nodes for ab1 (327 meshes,
   46 groups, 1 scatter, 2 code-refs), 10 for the chart — is data:
   geometry, materials with hash-shaded colours, group transforms,
   the 900-tuft annulus scatter, painter/file textures, camera,
   the house light, and the bokeh post chain.
